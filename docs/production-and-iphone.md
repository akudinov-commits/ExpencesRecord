# Production and iPhone setup

Production is https://expences-record.vercel.app, using the existing owner-only Google login and real annual expense workbook. Preview remains the isolated test environment. The initial production deployment and read-only hosted/security checks passed; evidence and physical-device status are recorded in the [release checklist](../ongoing-tasks/production-release-iphone-setup-checklist.md).

## Installation
Open the production URL in Safari on iPhone. Use Share (or More, then Share), choose Add to Home Screen, enable Open as Web App if offered, and tap Add. Open the new ExpencesRecord icon and sign in with the configured owner Google account. Home Screen and browser sessions can be separate, so verify login from the installed icon itself. No App Store or paid developer account is required. See [Apple's instructions](https://support.apple.com/en-az/guide/iphone/iphea86e5236/26/ios/26).

Verify category/currency choices, weekday/date, existing amount/formula/month total, Options appearance and safe-area layout. Only enter/save an actual intended expense; never use the real workbook for financial test submissions. A phone screenshot alone does not prove a completed save or fresh backend read-back. Record physical-device evidence separately from automated synthetic-session tests.

## Current limits and future periods
The real workbook has January-November 2026 tabs; all 334 dates are mapped explicitly. December has no tab and remains unavailable until the owner creates it and its mapping is verified. A new 2027 workbook also needs explicit configuration. Per-month rate references and native UAH storage/KZT aggregates follow the verified existing layout. Existing total definitions and all sheet data/formatting remain unchanged.

Basic Home Screen metadata/icons and existing safe-area styling are present. The app requires a network connection; it has no offline submission queue or service-worker cache. Reopening/reloading requests the deployed app normally; no background update guarantee is made. Preferred categories/currencies after closing remain roadmap feature 6. Existing seven-day login, explicit owner authorization, Origin/CSRF protection and preview/recheck/unknown-outcome limits remain unchanged.

## Operator delivery
Production uses separate private origin/cookie keys and the existing delegated owner Sheets grants; values and real workbook IDs never belong in Git. The user explicitly authorized Production and real-workbook activation. The current release uses a deliberate production build/deploy of the exact checked main commit through the existing CLI. The Preview-only GitHub deployment workflow is unchanged; pushing main alone does not automatically publish Production. Verify actual main CI before building/deploying. The initial local prebuild hit Windows symlink permission errors, so the verified release used a clean git-archive export of checked main with vercel deploy --prod and Vercel's cloud builder. No local credential/private configuration file was uploaded in that source export. Preserve the Preview alias/settings and verify health, default route protection, exact Google callback, owner-only read context and client/log isolation after deployment. Do not claim physical-device or Google-owner login from a manufactured test session.
