# Daily expense entry and reusable design system

## Goal
Let the signed-in owner enter and review current/past daily expenses with configured currency/category and optional cell comment, then see a truthful save result. Establish reusable visual tokens and accessible React components that future enhancements can compose.

## Scope
- **In scope:** the seven agreed steps below: interview/design approval; reusable design tokens/primitives/gallery/guidance; backward-compatible same-cell stack contract, optional monthly-category-total context read and typed API client; category/amount-stack/currency/date/comment form and gear-accessible Options with device-local appearance; conditional preview/warnings/confirmation; safe saving/result/comment-only recovery; mobile/accessibility and authorized checked Preview verification.
- **Out of scope:** persistent category/currency preferences or expense drafts, desktop/server preference sync, reporting screens/history beyond the requested selected-month category aggregate, offline queue, a new UI/query/form/router library or package by assumption, backend formula/FX/write changes beyond the explicitly approved same-cell amount-stack extension, Google credentials in FE, spreadsheet restructuring, real-workbook test writes/activation, full PWA installation/update/release and product Production.
- **Dependencies:** completed [backend](safe-expense-registration-backend-checklist.md), [mapping](spreadsheet-mapping-configuration-checklist.md), [authentication](google-login-private-access-checklist.md), [foundation](application-foundation-checklist.md), [roadmap](readme.md), [layer ADR](../adr/001-layer-boundaries.md), [auth ADR](../adr/003-google-authentication-and-access.md), [TDD ADR](../adr/006-tdd-and-feature-scope.md), [preview/write limits](../adr/007-expense-preview-and-write-limits.md).
- **Design gate:** step 01 includes the actual interview and approval of concrete flow/default/reset behavior, visual mockup, primitive set and proposed source/test layout before dependent implementation. Existing decisions remain valid; no speculative new boundary, dependency, storage or endpoint is selected by scaffolding.
- **Execution gate:** on 2026-11-27 the user requested implementation using session-start.md and execution.md, superseding scaffold-only status. Work is isolated on feature/daily-expense-entry-ui with the scaffold preserved. The recorded flow acceptance and Apple-inspired choice completed step 01 before dependent implementation; observed TDD remains mandatory. The user also requested conditional single-empty confirmation, Back instead of acknowledgment checkboxes and an Options page for appearance; theme-only local persistence is part of the recorded implemented Options design. The user selected a same-category/date/currency stack whose individual terms reach Sheets in one request/write. This clarifies step 03 to cover the necessary backward-compatible backend contract extension plus frontend client without adding/reordering steps. New fixture writes, credential uploads, publication, alias reassignment, commit/push, main merge or Production are not authorized merely by this execution request.

## Architecture
See [feature-architecture.md](daily-expense-entry-ui/feature-architecture.md). Shared UI stays generic; expense interaction state composes it and calls a central same-origin client. Existing backend application policy and security remain authoritative. Concrete UI/layout contracts follow the accepted Apple-inspired design and recorded interview choices.
