# Safe expense registration backend

## Goal
Register an owner-authorized daily expense in the existing date/category cell, preserving prior expenses, conversion formulas, totals, formatting and spreadsheet structure. Support optional real cell comments and report expense/comment outcomes honestly. Preview the selected cell, support past dates, warn about possible duplicates and reject detected stale previews without claiming strict concurrency or exactly-once delivery.

## Scope
- **In scope:** the five agreed steps below; formula/amount/currency/comment rules; owner-visible cell preview/confirmation, past-date entry and advisory duplicate signals; explicit limits of read-before-write conflict detection; controlled write consent; application-owned expense registration and exact write plans; protected transport; mechanical Sheets adapters; isolated verification and checked Preview handoff.
- **Out of scope:** changing or testing writes against the real workbook; spreadsheet restructuring/new ledger tabs or application metadata/receipt/lock storage; repairing existing totals/formulas; automatically creating annual workbooks/rate cells; computing FX in the app; expense UI, comment-entry UI, mobile preferences, offline queue, reporting/history product, product Production release or multiuser access.
- **Dependencies:** [completed mapping](spreadsheet-mapping-configuration-checklist.md), [authentication](google-login-private-access-checklist.md), [roadmap](readme.md), [layer boundaries](../adr/001-layer-boundaries.md), [Sheets authority](../adr/002-sheets-authority-and-year-routing.md), [Google access](../adr/003-google-authentication-and-access.md), [portability](../adr/004-vercel-and-portability.md), [TDD](../adr/006-tdd-and-feature-scope.md).
- **Design gate:** The user chose a simpler stateless preview/read-before-write approach, replacing the unaccepted metadata proposal. Exact preview/write/comment ports, amount precision/limits, supported grammar, storage-currency configuration, HTTP outcomes, acknowledgment flags, residual race limits and Preview routing were approved in steps 01-02 and implemented through this feature. No database, queue, new dependency/service, alternate hosting or workbook change is implicitly accepted. If safety requires changing those constraints, present concrete alternatives for approval before implementation.
- **Execution gate:** on 2026-11-26 the user requested execution using prompts/session-start.md and prompts/execution.md. The scaffold-only restriction is superseded for the five agreed steps. Steps 01-02 and the concrete isolated fixtures, separate write consent, private Preview transfer and feature publication were subsequently approved and verified as recorded below. The user explicitly approved merging/pushing to main. Any future real-workbook activation or Production release remains a separate decision.
